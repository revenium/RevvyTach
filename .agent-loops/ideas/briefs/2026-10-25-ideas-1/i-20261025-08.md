### Idea 8 (i-20261025-08) · Know where your terminal landed after every switch, and switch back in one click

**Their problem today.** You move your terminal between accounts with Make Active, a hotkey, or auto-switch. The app shows the new account as active but never checks the terminal followed. If the move fails, nothing says so; new terminals stay on the old account. Nothing records your moves, so going back means remembering.

**Their reality after.** Every switch ends with one checked line: "New terminals now use Spare" or "Terminal did not follow, still on Main", noting open terminals stay put. The popover lists recent switches; Switch Back (button or hotkey) returns you. When an account you left truly resets, a notification offers Switch Back. It never moves you back itself.

**Where you'd see it:** under the account after any switch (popover, Settings → Manage Profiles); "Recent switches" in the popover's Accounts footer; Settings → Shortcuts; macOS notifications.

**For example** (illustrative numbers)**.** Main hits its limit at 2:10 pm. You make Spare active: "New terminals now use Spare." At 4:40 pm Main resets and a notification offers Switch Back. One click; Spare kept 70% of its week.

**As a** developer with several Claude/Codex accounts, **when** I move my terminal to another account, **I want** proof it arrived and a one-click way back **so that** I never burn the wrong account unknowingly.

**Target user:** developer with several Claude/Codex accounts · **Strategy:** promise: "put my terminal on it in one click"; bet: "the terminal following via tmux and rc pointers".

**Already tracked:** nothing open. **What this adds:** a checked result, a record and an undo for every switch.

**Why it matters.** Moving the terminal is job 2, and its success is assumed, never checked. A silent failure spends the account you meant to save.

**Cost.** Effort L. **Biggest risk.** The reset notice must use the real reset, or it repeats false "session reset" alerts.
**An agent could build this unattended:** yes.
**Score** 20 of 25 = job value 4 × strategic fit 5. Demand none. Risk 3, effort L.

<details><summary>Evidence, mechanism, and the critic exchange</summary>

**Evidence.**
- Activation reports nothing back: `ProfileManager.activateProfile` (`Shared/Services/ProfileManager.swift:1144`) returns `Void`, and silently drops a request while another switch runs ("Profile switch already in progress, ignoring", 1145-1147).
- Claude: `ClaudeSwitchService.switchToAccount` (`Shared/Services/ClaudeSwitchService.swift:335-351`) throws if the account folder is missing or `.last-account` cannot be written; `activateProfile` logs that "non-fatal" (`ProfileManager.swift:1268-1276`) and still sets the active Claude profile (1286) and logs "Successfully activated" (1291). The Make Active button (`MenuBar/PopoverContentView.swift:852-861`) then disappears because the profile now reads as active. tmux failures are "— ignored" on both set (`ClaudeSwitchService.swift:850-854`) and unset (805-811).
- Codex: a failed CODEX_HOME switch is logged non-fatal and the home is cleared to the `~/.codex` default (`ProfileManager.swift:1196-1207`) while the linked profile shows active; tmux failures ignored (`Shared/Services/CodexSwitchService.swift:186-191, 219-224`).
- Auto-switch sends its banner unconditionally after `activateProfile` (`MenuBar/MenuBarManager.swift:4498-4502`), even when the switch was dropped or the pointer failed. Banner: `Resources/en.lproj/Localizable.strings:254-255`.
- Reset signal: the auto-switch flag clears on any `effectiveSessionPercentage < 100` (`MenuBarManager.swift:4463-4466`); effective % is zeroed once the stored reset time passes (`Shared/Models/ClaudeUsage.swift:22`), and it is only checked for the active profile.
- No switch history: only rollback snapshots and `updateActivationMetadata` overwriting one `lastUsedAt` (`Shared/Storage/ProfileStore.swift:1221-1236`). Next Profile is forward-only (`MenuBarManager.swift:4712-4725`; `Shared/Managers/ShortcutManager.swift:14-19`). No `UNNotificationAction`/`UNNotificationCategory` anywhere.
- Docs: `docs/multi-account-cli.md:215-218` (debug a wrong-account terminal by comparing `$CLAUDE_CONFIG_DIR` with `.last-account` by hand).

**Score inputs.**
- Job value 4: a large step on JTBD-2 (top three) for the primary user, since the check covers manual Make Active, not just auto-switch; capped at 4 (Make Active exists). Switch Back alone would be a 2.
- Strategic fit 5: promise "put my terminal on it in one click"; bet "the terminal following via tmux and rc pointers".
- Demand: none.
- Risk 3: changes the one activation path every switch uses; new notification actions; about 12 strings × 9 locales.
- Effort L whole idea; M for the first slice.

**What it would take.** Touch surface: `activateProfile` returns an outcome (dropped / switched / switched-but-terminal-did-not-follow) to all ~10 callers; a read-back of the app's own pointer files (`.last-account`, `.last-codex-home`) and `tmux show-environment -g`, never Codex auth or tokens; a small bounded journal (last ~50, both providers, scrubbed on profile delete, like `UsageHistoryService`); popover footer; `ShortcutManager` + Shortcuts settings; `NotificationManager` categories, action and delegate. The reset notice keys on the left account's own reset time passing plus a fresh reading, never the below-100% flag.
First slice: outcome + read-back line on every switch (manual, right-click, hotkey, auto-switch; Claude and Codex), banner text from the outcome, journal with Switch Back. Reset notice follows.
Revvie could implement unattended: yes for the outcome, journal and Switch Back (unit-testable); the live tmux read-back needs one human run on a real Mac before release.

**Risk in full.**
- Blast radius: every switch flows through `activateProfile`.
- Notification noise: a reset notice on a false reset is least-tolerated failure 7; one notice per reset, opt-out in Settings.
- Read-back limit: tmux and rc pointers reach only new shells; the line must say open terminals stay put, never imply they moved.
- Localization: about 12 strings, nine translations each.
- Privacy: journal holds profile names, times, causes; local, bounded, no telemetry.

**Alternatives.**
- Do nothing: failures stay invisible; users debug by hand per the docs.
- Fix only the defect (Make Active reports failure): closes the false success but gives no record, undo or proof of a good switch.
- Switch Back from `lastUsedAt` only: effort S, a convenience.
- Dropped from the first draft: the timed "use until Main resets" return (cannot stop a running `claude`; rides a weak reset signal) and ask-first for auto-switch.

**Strongest objection (critic).** OBJECTION-RESCOPES — Switch Back is a convenience; the receipt served only auto-switch, a secondary user. The timed borrow fails its example: tmux env reaches new shells only, so a running `claude` keeps spending Spare, and its "reset" fires on any reading under 100%. The real job-2 gap is wider: `activateProfile` returns Void and can silently skip; CLI-link and tmux failures are logged and ignored, so manual Make Active can claim a switch that never reached the terminal. Better slice: every switch reads back pointer and tmux state and says "terminal now on X" or "did not follow", plus journal-backed Switch Back, with the timed return replaced by a "Main has reset" notice carrying Switch Back. Score: value 3, risk 4, effort L.

**Response.** Scope grew. Every checkable claim held: the silent skip (`ProfileManager.swift:1145-1147`); the Claude pointer failure logged non-fatal (1274) with the profile still marked active (1286); tmux failures ignored (`ClaudeSwitchService.swift:805-811` is the unset path, the set path is 850-854); the flag clearing on any reading under 100% (`MenuBarManager.swift:4463-4466`). New shells only, so the borrow could not end the spend. Adopted the critic's slice: the check now covers every switch, timed return and ask-first are dropped, the reset notice keys on the real reset time. Value held at 4, not 3: once the check covers manual Make Active it serves the primary user on job 2, which is more than a convenience. Risk 3, not 4: the unattended return is gone. Effort L accepted. Separate defect for the bug loop: Make Active shows success when the terminal pointer write failed.

**Open questions for the owner.**
1. Journal length: last 20 switches, or a week?
2. Should the "has reset" notice be on by default, or opt-in like auto-switch?
