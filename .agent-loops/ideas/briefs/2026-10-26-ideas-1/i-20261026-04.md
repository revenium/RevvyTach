### Idea 4 (i-20261026-04) · Run separate kinds of work on separate accounts at the same time

**Their problem today.** One switch moves every new terminal on the Mac, so client work, personal work and an agent loop can't stay on separate accounts. Running a second account alongside means hand-typing a setup line. When a side account runs out, nothing notices: automatic switching watches only the active account.

**Their reality after.** They name a few "lanes", such as client and loop, each on its own account. A lane is a label a terminal carries, set on a tmux session or a terminal profile. Make Active works per lane. When a lane's account hits its limit, only that lane moves, onto an account no other lane uses. Unlabelled terminals follow today's switch. "Copy launch command" opens one terminal on any account without moving anything.

**Where you'd see it:** right-click any account in the menu bar or Health strip → "Copy launch command" and "Use for lane…"; a lane tag in the popover Accounts list; Settings → CLI Account → Lanes.

**For example** (illustrative numbers)**.** Eight accounts, three lanes. At 14:10 the loop's Max hits its limit; the loop lane moves to an idle Max. Personal and client never notice.

**As a** developer with several accounts, **when** I run separate kinds of work in parallel, **I want** each kept on its own account **so that** switching or running out in one never moves the others.

**Target user:** developer with several Claude/Codex accounts · **Strategy:** "put my terminal on it in one click"; "the terminal following via tmux and rc pointers"

**Already tracked:** nothing open. **What this adds:** named lanes, each with its own switch, plus a launch command for both providers.

**Why it matters.** It serves JTBD-2 (move the terminal with me) for accounts used in parallel.

**Cost.** Effort L. **Biggest risk.** Per-lane automatic switching changes shipped automation; a wrong move puts two lanes on one account.
**An agent could build this unattended:** no.
**Score** 20 of 25 = job value 4 × strategic fit 5. Demand none. Risk 4, effort L.

**Risk in full.**

- Auto-switch: two lanes must never be moved onto one account; "all accounts busy" must say so, not double up.

**Strongest objection (critic).** OBJECTION-RESCOPES — The tmux session is the wrong unit, and the brief's own example shows it. "loop" is pinned to a spare Max, and agent loops are what burn through limits. When that Max runs out, auto-switch moves only the global slot. "personal" gets dragged and "loop" stalls on a dead account, so the parallel case breaks at the moment it exists for. Pins also vanish when the tmux server restarts, and they do nothing for terminals outside tmux (Ghostty or iTerm tabs, VS Code). The better slice is named lanes. Each lane gets its own pointer file (`.last-account.<lane>`, which survives restarts). The copy-only snippet reads `$REVVYTACH_LANE` and falls back to today's global file. The app can set that variable per tmux session, or the user can put it in a terminal profile. Make Active and auto-switch work per lane and never put two lanes on one account. Copy launch command ships first either way. The real risk is per-lane auto-switch, not snippet migration alone.
